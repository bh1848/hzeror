## 시뮬레이션 규모 확대에 따른 Throughput 급감

D-HASH 알고리즘의 유효성을 검증하기 위해 노드 간 데이터 분산 시뮬레이션을 수행하던 중, 처리 데이터 규모가 커질수록 **처리량(Throughput)**이 급감하고 **메모리 점유율(Memory Footprint)**이 비정상적으로 치솟는 현상을 확인했다.

초기 프로파일링 결과, 병목 지점은 크게 두 곳이었다. 첫째는 해싱 연산(`get_node`)에서의 CPU 점유율이 과도하게 높았고, 둘째는 수백만 개의 키(Key) 객체를 생성하는 과정에서 Python 프로세스의 메모리 사용량이 물리 메모리 한계에 육박했다.

이 현상은 단순히 로직의 복잡성 때문에 발생하는 것이 아니라, **내가 기반 기술로 선택한 해시 알고리즘(MD5)과 Python 객체 모델의 구조적 한계** 때문에 발생하는 것이다.

## MD5의 암호학적 비용과 연산 오버헤드

초기 설계 단계에서 나는 분산 시스템의 데이터 정합성을 위해, 실행 환경(OS, Python 버전)에 관계없이 항상 동일한 해시값을 보장하는 **MD5**를 채택했다. Python 내장 `hash()` 함수는 보안상의 이유로 프로세스 실행 시마다 시드(Seed)가 무작위로 변경되어 재현성이 떨어지기 때문이다.

하지만 MD5는 충돌 저항성(Collision Resistance)을 확보하기 위해 복잡한 비트 연산을 수행하므로, 단순한 로드 밸런싱이나 데이터 샤딩(Sharding) 목적으로 사용하기에는 연산 비용(CPU Cycle)이 매우 비싸다.

> 초당 수십만 회 이상의 해싱이 필요한 시뮬레이터에서 MD5와 같은 암호화 해시 함수는 명백한 오버 스펙이다. 나는 데이터 분산에는 '보안'이 아닌 '속도'와 '분포도'가 최우선순위라고 판단했다.

## Python 동적 객체 모델과 __dict__의 메모리 낭비

또한 Python의 클래스 인스턴스는 기본적으로 속성을 `__dict__`라는 딕셔너리 형태로 관리한다. 이는 런타임에 속성을 동적으로 추가할 수 있는 유연성을 제공하지만, 내부적으로 해시 테이블을 유지해야 하므로 객체당 메모리 오버헤드가 크다.

D-HASH 실험과 같이 수십만 개의 객체를 다루는 환경에서는 이 작은 오버헤드가 누적되어 GB 단위의 낭비를 초래하며, 잦은 GC(Garbage Collection)를 유발해 성능 저하의 주원인이 된다.

## xxHash64 도입과 __slots__ 메모리 최적화

나는 이 문제를 해결하기 위해 두 가지 결단을 내렸다.
첫째, 암호학적 안전성을 포기하는 대신 압도적인 연산 속도를 제공하는 **xxHash64** 알고리즘을 도입했다.

> **[xxHash](https://github.com/Cyan4973/xxHash)**  
> 매우 빠른 속도를 목표로 설계된 비암호화 해시 알고리즘이다. 시드(Seed) 값을 고정할 수 있어 분산 환경에서 내가 요구하는 해시 일관성(Consistency)을 완벽히 충족한다.

~~~python
# xxHash 라이브러리 활용
try:
    import xxhash as _xx
except ImportError:
    raise RuntimeError("xxhash package required")

def fast_hash64(key: Any) -> int:
    """Computes a 64-bit non-cryptographic hash using xxHash."""
    # MD5 대비 수십 배 빠른 속도와 결정적(Deterministic) 결과 보장
    # digest()보다 빠른 intdigest()를 사용하여 정수형 해시값 즉시 반환
    return _xx.xxh64(str(key).encode("utf-8")).intdigest()
~~~

둘째, 객체 생성 오버헤드를 줄이기 위해 `DHash` 클래스에 `__slots__`를 명시했다. 이를 통해 Python 인터프리터에게 지정된 속성 외에는 사용하지 않겠다고 선언함으로써, `__dict__` 생성을 차단하고 고정된 메모리 공간만을 할당하도록 강제했다.

~~~python
class DHash:
    # __dict__ 생성을 억제하여 메모리 사용량 최적화
    # 고정된 속성만 허용하여 객체당 메모리 오버헤드 감소
    __slots__ = ("nodes", "T", "W", "reads", "alt", "ch", "hot_key_threshold")
~~~

## 성능 향상 지표와 엔지니어링 트레이드오프

최적화 적용 후 벤치마크를 수행한 결과, 해싱 연산 속도는 기존 MD5 대비 **약 $20$배 이상 향상**되었다. 또한 `__slots__` 적용을 통해 객체당 메모리 소비량을 약 **$40 \sim 50\%$ 절감**했다. 결과적으로 가비지 컬렉션(GC) 빈도가 낮아져 벤치마크 결과의 안정성(Jitter 감소)을 확보했다.

내가 적용한 이 아키텍처는 명확한 **트레이드오프**를 가진다. 보안 시스템에서는 MD5가 필수적이지만 시뮬레이터에서는 속도가 더 중요했고, `__slots__`는 Python의 동적 속성 할당이라는 유연성을 영구적으로 제한한다. 하지만 대용량 트래픽을 검증하는 현재의 벤치마크 도메인 환경에서는 처리량과 메모리 절감이 그 어떤 유연성보다 가치 있는 선택이었다.
