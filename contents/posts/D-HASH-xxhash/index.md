## 시뮬레이션 규모 확대에 따른 Throughput 급감

D-HASH 알고리즘의 유효성을 검증하기 위해 노드 간 데이터 분산 시뮬레이션을 수행하던 중, 처리 데이터 규모가 커질수록 **처리량(Throughput)**이 급감하고 **메모리 점유율(Memory Footprint)**이 비정상적으로 치솟는 현상이 관측되었다.       

초기 프로파일링 결과, 병목 지점은 크게 두 곳이었다. 첫째는 해싱 연산(`get_node`)에서의 CPU 점유율이 과도하게 높았고, 둘째는 수백만 개의 키(Key) 객체를 생성하는 과정에서 Python 프로세스의 메모리 사용량이 물리 메모리 한계에 육박했다.     

이 현상은 단순히 로직의 복잡성 문제가 아니라, **기반 기술로 선택한 해시 알고리즘(MD5)과 Python 객체 모델의 구조적 한계**에서 기인한 것이다.     

## MD5의 암호학적 비용과 연산 오버헤드

초기 설계 단계에서는 분산 시스템의 데이터 정합성을 위해, 실행 환경(OS, Python 버전)에 관계없이 항상 동일한 해시값을 보장하는 **MD5**를 채택했다. Python 내장 `hash()` 함수는 보안상의 이유로 프로세스 실행 시마다 시드(Seed)가 무작위로 변경되어 재현성이 떨어지기 때문이다.        

하지만 MD5는 **'암호학적 안전성(Cryptographic Security)'**을 목표로 설계된 알고리즘이다. 충돌 저항성(Collision Resistance)을 확보하기 위해 복잡한 비트 연산을 수행하므로, 단순한 로드 밸런싱이나 데이터 샤딩(Sharding) 목적으로 사용하기에는 연산 비용(CPU Cycle)이 매우 비싸다.        

> **오버 스펙의 함정**  
> 초당 수십만 회 이상의 해싱이 필요한 시뮬레이터에서 MD5와 같은 암호화 해시 함수는 명백한 오버 스펙이다. 데이터 분산에는 '보안'이 아닌 '속도'와 '분포도'가 우선순위다.      

## Python 동적 객체 모델과 __dict__의 메모리 낭비

또한 Python의 클래스 인스턴스는 기본적으로 속성을 `__dict__`라는 딕셔너리 형태로 관리한다. 이는 런타임에 속성을 동적으로 추가할 수 있는 유연성을 제공하지만, 내부적으로 해시 테이블을 유지해야 하므로 객체당 메모리 오버헤드가 크다.        

D-HASH 실험과 같이 수십만 개의 객체를 다루는 환경에서는 이 작은 오버헤드가 누적되어 GB 단위의 낭비를 초래하며, 잦은 GC(Garbage Collection)를 유발해 성능 저하의 주원인이 된다.      

## xxHash64 도입을 통한 연산 가속

이 문제를 해결하기 위해 첫 번째로 **xxHash64** 알고리즘을 도입했다. `xxHash`는 암호학적 안전성을 포기하는 대신, RAM 속도 한계에 가까운 압도적인 연산 속도를 제공한다. 또한 시드(Seed) 값을 고정할 수 있어 분산 환경에서 필수적인 **해시 일관성(Consistency)**도 보장된다.       

> **[xxHash](https://github.com/Cyan4973/xxHash)란?**       
> 매우 빠른 속도를 목표로 설계된 비암호화 해시 알고리즘이다. 데이터 무결성 검사나 해시 테이블 구현 등 고성능이 요구되는 분야에서 MD5나 SHA-1의 대체제로 널리 사용된다.      

~~~python
# xxHash 라이브러리 활용
try:
    import xxhash as _xx
except ImportError:
    raise RuntimeError("xxhash package required")

def fast_hash64(key: Any) -> int:
    """Computes a 64-bit non-cryptographic hash using xxHash."""
    # MD5 대비 수십 배 빠른 속도와 결정적(Deterministic) 결과 보장
    # digest()보다 빠른 intdigest()를 사용하여 정수형 해시값 즉시 반환
    return _xx.xxh64(str(key).encode("utf-8")).intdigest()
~~~

## __slots__를 이용한 메모리 구조 최적화

두 번째로 객체 생성 오버헤드를 줄이기 위해 `DHash` 클래스에 `__slots__`를 명시했다. 이를 통해 Python 인터프리터에게 "이 클래스는 지정된 속성 외에는 절대 사용하지 않는다"고 선언함으로써, 동적 딕셔너리(`__dict__`) 생성을 차단하고 C 구조체(struct)와 유사한 고정된 메모리 공간만을 할당하도록 강제했다.       

~~~python
class DHash:
    # __dict__ 생성을 억제하여 메모리 사용량 최적화
    # 고정된 속성만 허용하여 객체당 메모리 오버헤드 감소
    __slots__ = ("nodes", "T", "W", "reads", "alt", "ch", "hot_key_threshold")
~~~

## 해싱 속도 20배 향상 및 메모리 50% 절감 성과

최적화 적용 후 마이크로 벤치마크를 수행한 결과, 해싱 연산 속도는 기존 MD5 대비 **약 $20$배 이상 향상**되었다. 이는 전체 시뮬레이션의 처리량(OPS) 증가로 직결되었으며, 특히 해싱 연산이 집중되는 로드 밸런싱 구간의 레이턴시를 획기적으로 낮췄다.        

또한 `__slots__` 적용을 통해 객체당 메모리 소비량을 약 **$40 \sim 50\%$ 절감**했다. 이는 동일한 하드웨어 리소스($16GB$ RAM)에서 더 많은 키와 노드를 시뮬레이션할 수 있게 되었음을 의미하며, 가비지 컬렉션(GC) 빈도를 낮추어 벤치마크 결과의 안정성(Jitter 감소)을 확보하는 부수적인 효과까지 얻었다.        

## 보안과 성능 사이의 엔지니어링 트레이드오프

이번 최적화는 **"안전한 것이 항상 좋은 것은 아니다"**라는 엔지니어링의 트레이드오프를 잘 보여준다.      

> 보안이 중요한 인증 시스템에서는 MD5(혹은 SHA-256)가 필수적이지만, 고성능이 요구되는 내부 데이터 처리 로직에서는 xxHash와 같은 특화된 알고리즘이 훨씬 합리적인 선택이다.       

또한 `__slots__`를 사용하면 런타임에 동적으로 속성을 추가하는 Python 특유의 유연성이 제한되므로, 클래스 설계가 완전히 확정된 시점에 도입하는 것이 바람직하다. 대규모 트래픽을 처리하는 백엔드 시스템에서는 언어 내부의 동작 원리를 이해하고 작은 최적화를 쌓아가는 것이 전체 시스템의 확장성(Scalability)을 결정짓는 핵심 요소가 된다.
