## 트랜잭션의 정의
트랜잭션은 데이터베이스의 상태를 변화시키기 위해 수행하는 **하나의 연속적인 업무 단위**를 의미한다. 데이터 모델링 단계에서 트랜잭션을 이해하는 것은 업무의 흐름과 데이터 무결성을 정의하는 기초가 된다.

- **업무 수행의 단위**: 하나의 트랜잭션 내에는 여러 개의 조회, 삽입, 삭제, 수정 연산이 포함될 수 있으며, 이들은 하나의 논리적 단위로 묶인다.
- **원자성**: 트랜잭션 내의 작업들은 '모 아니면 도'로 처리된다. 모든 연산이 성공하여 **COMMIT**되거나, 하나라도 실패하여 **ROLLBACK**되어야 하며 부분 반영은 불가능하다.



## 필수적·선택적 관계와 트랜잭션
데이터 모델링 시 엔터티 간의 관계가 필수인지 선택인지에 따라 트랜잭션의 범위와 데이터 생성 순서가 결정된다.

- **필수적 관계**: 두 엔터티의 관계가 서로 필수적일 때, 보통 하나의 트랜잭션 내에서 데이터가 함께 처리된다.
    - **예시**: '주문'과 '주문상세'는 필수 관계다. 주문 메인 정보만 있고 상세 내역이 없는 데이터는 무결성에 어긋나므로, 반드시 하나의 트랜잭션으로 묶어 처리한다.
- **선택적 관계**: 두 엔터티가 서로 독립적으로 수행 가능하다면 선택적 관계로 표현한다.
    - **예시**: '고객'과 '이벤트참여'는 선택 관계다. 고객 정보 생성 트랜잭션과 이벤트 참여 트랜잭션은 시점과 목적이 다르므로 독립적으로 수행된다.



## 관계 표기법 비교
선택성을 구분하는 방식은 표기법에 따라 다르므로 정확히 암기해야 한다.



### 1. IE 표기법
관계를 나타내는 선의 끝부분 기호를 확인한다.
- **필수적 관계**: 관계선 끝에 원이 없다.
- **선택적 관계**: 관계선 끝에 **원**을 그려 데이터가 없을 수도 있음을 표시한다.

### 2. Barker 표기법
관계선의 모양(실선/점선)을 통해 구분한다.
- **필수적 관계**: 관계선을 **실선**으로 표기한다.
- **선택적 관계**: 관계선을 **점선**으로 표기한다.



## 트랜잭션 분석과 모델 검증
데이터 모델링 완료 후, 실제 비즈니스 트랜잭션이 해당 모델을 통해 원활히 수행되는지 검증해야 한다.
- **CRUD 매트릭스**: 엔터티에 대해 트랜잭션이 **CREATE, READ, UPDATE, DELETE** 중 어떤 작업을 하는지 매핑하여 누락된 관계나 속성을 찾는다.
- **병목 지점 파악**: 특정 엔터티에 트랜잭션이 집중(Hot Spot)되어 성능 저하가 우려될 경우, 반정규화 등을 통해 부하를 분산한다.



> **💡 [Tip] 트랜잭션과 관계**  
> 1. **표기법 함정**: "Barker 표기법에서 실선은 선택적 관계를 의미한다"는 선지는 자주 나오는 오답이다. **실선=필수, 점선=선택**임을 명심하자.  
> 2. **원자성 원칙**: 트랜잭션의 원자성 때문에 오류 발생 시 이전까지 성공한 작업도 모두 취소(**ROLLBACK**)되어야 한다는 점이 문제로 출제된다.  
> 3. **선택적 관계의 물리적 의미**: 선택적 관계는 물리 모델에서 **Nullable** 컬럼으로 구현되며, 조인 시 데이터 누락을 방지하기 위해 **OUTER JOIN**이 필요할 수 있음을 연계하여 이해하자.
