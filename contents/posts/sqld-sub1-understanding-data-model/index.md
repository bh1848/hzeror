## 데이터 모델링의 정의 및 추상화
데이터 모델링은 복잡한 비즈니스 프로세스를 데이터베이스에 수용하기 위해 **추상화**, **단순화**, **명확화**를 수행하는 과정이다. 단순히 테이블을 생성하는 작업을 넘어, 시스템 아키텍처의 **병목**을 방지하고 데이터 **정합성**을 보장하기 위한 설계도를 그리는 작업이다.

### 모델링의 3단계 계층 구조
- **개념적 데이터 모델링**
    - 전사적 관점에서 엔터티 간의 관계를 정의한다. 추상화 수준이 가장 높으며 ERD를 통해 핵심 로직을 가시화한다.
- **논리적 데이터 모델링**
    - 특정 DBMS에 종속되지 않은 상태에서 정규화를 수행한다. 재사용성과 정합성을 확보하는 가장 중요한 단계다.
- **물리적 데이터 모델링**
    - 실제 저장 장치에 데이터가 생성되는 단계다. 성능, 저장 효율, **레이턴시**를 고려하여 인덱스 설계 및 파티셔닝을 수행한다.



## 데이터 모델의 독립성 (3층 스키마)
데이터 독립성은 유지보수 비용을 낮추고 시스템 유연성을 확보하기 위해 필수적이다. ANSI-SPARC에서 정의한 3층 스키마 구조는 각 계층의 독립성을 보장함으로써 **데이터 복잡도**를 관리한다.



- **외부 스키마**: 사용자나 개발자 관점에서 개별적으로 보는 뷰를 의미한다.
- **개념 스키마**: 모든 사용자의 관점을 통합하여 조직 전체의 논리적 구조를 정의한 형태다.
- **내부 스키마**: 실제 물리적 저장 장치에서 데이터가 배치되고 인덱스가 구성되는 구조다.

### 데이터 독립성을 위한 사상(Mapping)
하위 계층이 변경되어도 상위 계층에 영향을 주지 않도록 연결하는 논리적 장치다.
- **논리적 사상**: 외부 스키마와 개념 스키마를 연결하며, 개념 구조가 바뀌어도 개별 사용자 뷰는 유지되는 **논리적 독립성**을 보장한다.
- **물리적 사상**: 개념 스키마와 내부 스키마를 연결하며, 저장 장치 구조가 바뀌어도 전체 논리 구조는 유지되는 **물리적 독립성**을 보장한다.



## 모델링의 3요소와 실무 예시
데이터 모델링은 '어떤 것', '성격', '관계'로 구성된다.

- **엔터티 (Entity)**
    - 업무에서 관리해야 하는 대상으로서 고유한 식별이 가능한 객체다. 
    - **예시**: 쇼핑몰 시스템에서 고객의 개인정보를 관리하는 '회원'이나 판매되는 물품 정보를 담는 '상품'은 독립적인 엔터티로 정의하자.
- **속성 (Attribute)**
    - 엔터티가 가지는 최소 단위의 데이터 항목이다.
    - **예시**: '회원' 엔터티는 로그인에 필요한 '아이디', 본인 확인을 위한 '이메일', 가입 날짜를 기록하는 '가입일' 등의 속성을 가진다.
- **관계 (Relationship)**
    - 엔터티 간에 존재하는 논리적인 연관성이다.
    - **예시**: 특정 '회원'이 장바구니에 담긴 '상품'을 결제하여 '주문'하는 행위는 엔터티 간의 유기적인 연관 관계를 형성한다.



## 데이터 모델링의 정합성 검증 원칙
부적절한 모델링은 데이터 중복과 **이상 현상**을 유발한다. 이를 방지하기 위한 세 가지 기본 원칙을 준수해야 한다.

- **중복 금지**: 동일한 데이터를 여러 곳에 저장하여 데이터 간 불일치가 발생하는 상황을 원천 배제하자.
- **유연성**: 업무 로직이 변경되더라도 데이터 구조를 통째로 뜯어고치는 일 없이 대응이 가능해야 한다.
- **일관성**: 데이터 간에 논리적 모순이 없어야 하며, 수정 발생 시 연관된 데이터들이 명확한 상태를 유지해야 한다.

~~~sql
-- 엔터티 정합성 유지를 위한 DDL 예시
CREATE TABLE MEMBER (
    MEMBER_ID VARCHAR(20) PRIMARY KEY, -- 식별자 유일성 보장
    EMAIL VARCHAR(50) NOT NULL UNIQUE, -- 중복 방지 및 인덱싱 오버헤드 고려
    CREATED_AT TIMESTAMP DEFAULT CURRENT_TIMESTAMP 
);

-- 관계 엔터티 정의 (Foreign Key)
CREATE TABLE ORDER_INFO (
    ORDER_ID BIGINT PRIMARY KEY,
    MEMBER_ID VARCHAR(20),
    CONSTRAINT FK_MEMBER FOREIGN KEY (MEMBER_ID) REFERENCES MEMBER(MEMBER_ID)
);
~~~



> **💡 [Tip] 데이터 독립성과 사상**  
> 1. **사상의 명칭**: 논리적 사상(외부-개념)과 물리적 사상(개념-내부)을 서로 매칭하는 문제는 1과목의 단골 문항이다.  
> 2. **독립성의 정의**: 저장 장치의 구조가 바뀌어도 데이터 논리 구조가 변하지 않는 것이 **물리적 독립성**임을 기억하자.  
> 3. **3대 요소 구분**: 엔터티, 속성, 관계 중 하나를 빠뜨리거나 엉뚱한 용어를 넣는 보기를 골라낼 수 있어야 한다.
