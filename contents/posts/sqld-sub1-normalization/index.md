## 정규화의 정의
정규화는 데이터의 일관성 유지, 중복 최소화, 유연성 최대화를 위해 엔터티를 최소 단위로 분해하는 과정이다. 논리 데이터 모델링 시점에서 수행하며, 이를 통해 데이터 모델의 독립성을 확보하고 **이상현상**을 방지한다.

- **정규화의 목적**
    - 데이터 중복 제거를 통한 저장 공간 효율화 및 데이터 정합성 유지
    - 데이터 모델의 유연성 향상 및 엔터티 상세화
    - 삽입, 갱신, 삭제 시 발생하는 **이상현상** 방지



## 이상현상
정규화를 거치지 않아 데이터 모델이 불완전할 때 발생하는 부작용이다.

- **삽입 이상**: 데이터를 입력할 때 불필요한 정보까지 강제로 입력해야 하거나, 정보 부족으로 입력이 불가능한 현상이다.
- **갱신 이상**: 중복 데이터 중 일부만 수정되어 데이터 간 불일치가 발생하는 현상이다.
- **삭제 이상**: 특정 정보를 삭제할 때 유지되어야 할 다른 정보까지 연쇄적으로 삭제되는 현상이다.



## 정규화 단계 (1NF ~ BCNF)
실무와 시험에서는 주로 제3정규화와 BCNF까지의 과정을 중요하게 다룬다.



### 1. 제1정규화 (1NF): 속성의 원자성 확보
- **수행**: 모든 속성이 **원자값**을 갖도록 한다. 하나의 컬럼에 여러 값이 들어간 다중값 속성을 분리한다.
- **예시**: '회원' 엔터티의 '취미' 속성에 '축구, 영화'가 함께 있다면 이를 별도의 인스턴스나 엔터티로 분리한다.

### 2. 제2정규화 (2NF): 부분 함수 종속성 제거
- **수행**: 기본키가 복합키일 때, 기본키의 **일부분에만 종속**되는 속성을 분리한다.
- **예시**: {학번, 과목코드}가 PK일 때, '학생이름'은 '학번'에만 종속되므로 {학번, 학생이름}으로 분리하여 완전 함수 종속을 만든다.

### 3. 제3정규화 (3NF): 이행적 종속성 제거
- **수행**: 기본키를 제외한 일반 속성 간의 종속 관계를 제거한다. ($A \rightarrow B \rightarrow C$ 관계 분리)
- **예시**: '학번(PK)'이 '소속학과'를 결정하고, '소속학과'가 '학과장명'을 결정할 때 {학번, 소속학과}와 {소속학과, 학과장명}으로 분리한다.

### 4. BCNF (Boyce-Codd Normal Form)
- **수행**: 모든 **결정자가 후보키**가 되도록 분해한다. 후보키가 아닌 속성이 결정자 역할을 하는 경우를 제거한다.



## 정규화와 성능
정규화는 데이터 모델의 정합성을 높여주지만 성능 면에서는 양면성을 가진다.

- **DML 성능 향상**: 중복 데이터와 데이터 양이 줄어들어 **INSERT, UPDATE, DELETE** 성능이 좋아진다.
- **조회 성능 저하 가능성**: 테이블이 세분화됨에 따라 데이터 조회 시 **조인(Join)**이 증가하여 처리 속도가 느려질 수 있다. 이를 해결하기 위해 나중에 **반정규화**를 검토한다.



> **💡 [Tip] 정규화 단계 암기법 '도-부-이-결-다-조'**  
> 1. **도**: 모든 값이 **도**메인 원자값 (1NF)  
> 2. **부**: **부**분 함수 종속 제거 (2NF)  
> 3. **이**: **이**행 함수 종속 제거 (3NF)  
> 4. **결**: **결**정자이면서 후보키가 아닌 것 제거 (BCNF)  
> 5. **다**: **다**치 종속 제거 (4NF)  
> 6. **조**: **조**인 종속 제거 (5NF)  

> **주의**: 시험에서 "정규화는 조인 횟수를 줄여 조회 성능을 향상시킨다"는 지문은 대표적인 **오답**이다. 정규화는 조인 횟수를 **늘린다**는 점을 명심하자.
